## Mission and development-trial configuration

The existing `M-VERTEX` now uses the wording already present in
`bottom-corner-000-20261017-3`:

> The Cube shall balance on each of its 8 corners with its 3 reaction wheels.

The acceptance criterion is `distinct_corners_demonstrated == 8` in the
hardware domain. The planned `cube.verify.M-VERTEX` case has the same
criterion. Its execution status remains `not_run`.
Existing hold, tilt, RMS and other obligations retain their meanings.

`R-FIRST-CORNER`, `R-WHEEL-MOUNT-000` and `D-WHEEL-MOUNT-SIDE` describe the first
development configuration: support corner `000` and fixed lower-face mounts.
Keep that scope distinct from mission achievement. Completing this trial adds
no claim about the other seven corners. The current corner-000 equilibrium and
observation transform do not implement eight-corner simulation.

## Smallest optimization unit

Use one independent permitted input together with its derived model changes as
the smallest experimental change unit. Recompute dependent quantities through
the design configuration builder. Select useful units through their existing requirement links.

The current design configuration builder (`compile_mechanical` in code) validates
inputs, derives physical quantities and creates simulation settings. It exposes
six continuous inputs:

- `side_m`: corresponds directly to `D-SIDE`. It also changes wheel radius,
  printed mass, fixed-part mass, frame inertia and wheel inertia.
- `print_mass_ref_kg`: sets reference printed mass. Fixed-part mass and frame
  inertia follow from the scale and component package. It is not a free override
  of measured `I-FRAME-MASS`.
- `wheel_mass_kg`: changes the ring mass and wheel inertia. The compiled
  `D-WHEEL-MASS` also includes motor rotor mass, so these two values differ.
- `wheel_radius_ratio`: sets wheel radius relative to side length, then wheel
  inertia. `D-WHEEL-RADIUS` is derived for that candidate.
- `inner_radius_ratio`: changes axial and transverse wheel inertia in the ring
  approximation. The current registry has no dedicated KDP for this input.
- `wheel_thickness_m`: changes thickness and transverse inertia. With mass and
  radius fixed, it does not change axial inertia in the current design configuration builder.

For example, `wheel_radius_m = side_m * wheel_radius_ratio`. Those three values
are not three independent coordinates. Frame inertia and wheel inertia also
follow from the chosen geometry and mass; do not optimize them again as free
values. A one-coordinate experiment supplies all six required mechanical fields
and retains the other five values.

Motor family is an existing discrete component-package choice. Four optional
controller inputs also exist: `tilt_q_scale`, `rate_q_scale`, `momentum_q_scale`
and `yaw_rate_gain_nm_s`. They have no dedicated IDs in the selected 37-KDP
registry. This inventory does not select every available input for optimization
or introduce new KDPs.

The `design` role alone does not authorize optimization. `D-BUDGET` is a human
acceptance limit. `D-SPEED-LIMIT` is an assembly limit to substantiate and obey.
`D-CORNER-R` is outside the current design configuration builder proposal allowlist. Keep their
roles separate from the six permitted mechanical inputs.

## Controller algorithm change boundary

The authoritative contract is `cube.change-contract.control-algorithm@refined-20261115-1`.
Future software edits may revise the control algorithm, internal controller state
and gain calculation in `balancing-cube-simulation/balancing_cube/control.py`.
Plant/contact physics, sensor observations, actuator limits, timing, requirements,
test conditions, scoring and evidence recording remain outside this permission.

This revision records the authorized scope only. The current Engineering Agents
runtime still accepts gain parameters. Code proposals and execution require a
later implementation connecting the controller interface to native and requested
accelerated runners, with candidate source hashes. The reference file is not
currently called by every runner.

## Requirement duplication and reference granularity

The selected model contains 22 obligations, 7 groups and 37 KDPs: 6 design,
29 identification and 2 fixed parameters. Their physical values and uncertainty
fields retain their source values.

Fourteen KDP records previously referenced `C-FIT` or `R-DRIVE` groups. Their
references now identify atomic requirements by reversing the existing `constrain`
links. Groups remain available for classification. Examples:

- `D-SIDE`: `C-FIT` becomes `C-FIT-INSTALL` and `C-FIT-PRINT`; `R-HOLD` remains.
- `D-WHEEL-RADIUS`: `C-FIT` and `R-DRIVE` become `C-FIT-INSTALL` and
  `R-DRIVE-SPEED`.
- `I-PEAK-TORQUE`: `R-DRIVE` becomes `R-DRIVE-TORQUE`; `R-HOLD` remains.
- `I-PRINT-X/Y/Z`: `C-FIT` becomes `C-FIT-PRINT`.

The structured proposal includes all fourteen before/after changes with exact
source revisions. This repairs reference granularity without adding a new
physical relationship or claiming measured influence on performance.

`C-PRINT` is a consolidation candidate because its acceptance criterion
delegates to `C-FIT-PRINT`. Count that delegated test once. Before retiring the
broader manufacture statement, resolve whether it carries intent beyond the
size check and existing `C-FIT-MATERIAL` obligation. It remains an obligation.

`R-TILT` and `R-RMS` allocate to balance control but have no direct KDP
`constrain` links. Review the existing derived model dependencies when selecting
optimization inputs. Do not invent a ranking of parameter influence from a
link alone.

## Boundary of this refinement

This revision adds no requirement IDs, parameter IDs, measurement campaign,
robustness objective or recovery-time objective. The next scoring work uses
mandatory requirement verdicts and deficits, with zero additional precision
credit after the applicable requirement is met. A gate or score revision still
needs its own explicit evaluation contract.

Historical source revisions, numerical results and evidence applicability remain
attached to their original configurations. The eight-corner wording is a mission
obligation, not a result from the existing one-corner trials.
