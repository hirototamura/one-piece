# 8頂点のミッションと初回試験

ユーザーは2026年10月17日に、Cubeの8頂点それぞれで倒立保持するミッションを明確にした。
最初の開発試験は頂点`000`のみを対象とする。[英語の要求文](../en/bottom_corner_trial.md)が原文であり、日本語はその翻訳である。
正式な文言は草案のままである。採用ベースラインや実機結果を確定したものではない。

## 正本の記録

現在の表示用構成は`cube.simulation.snapshot@bottom-corner-000-20261017-3`を選択する。
要求・要求グループ31件とKDP・パラメータ38件を固定し、英語の標準対応草案から派生している。
以前の研究は、当時の要求の版、モデル、結果を保持する。

- `M-VERTEX`：「Cubeは、3個のリアクションホイールを用いて8頂点のそれぞれで倒立保持しなければならない。」
- `R-FIRST-CORNER`：「最初の開発シミュレーションは、Cubeを頂点000で評価しなければならない。」
- `R-WHEEL-MOUNT-000`：「初回試験モデルは、3個のリアクションホイールを頂点000に接する3面に配置しなければならない。」
- `D-WHEEL-MOUNT-SIDE`：`physics.wheel_mount_side`に結び付く固定値`near_corner_000`。

これらの版は`bottom-corner-000-20261017-3`である。
経路はミッション→システムの試験範囲→サブシステムの取付制約となる。
取付要求はパラメータとスナップショットを制約する。派生設計は要求への対応意図を記録する。
数値的証拠は開発試験ケースを検証する。計画段階の実機試験ケースは検証済みの証拠ではない。

頂点000を機体座標の原点とし、Cubeは3軸の正方向に広がる。
ホイール中心は`(inset,s/2,s/2)`とその2つの軸の置換である。物理的な取付面は固定する。
将来の別頂点の試験は、実際の合成重心から釣り合い姿勢を定義しなければならない。
ホイールを暗黙に移動したり、頂点000用の観測変換がそのまま使えると仮定したりしてはならない。
残り7頂点の支持モデルは今回の変更では実装していない。

## 制御器と証拠

暫定構成は`cube-f069bd6e148e43e0a411.candidate.10@1`のMASS試験で保存した制御器を保持する。
`controller_design_snapshot_ref`が過去の公称設計プラントを固定する。
Engineering Agentsは、後のQ重みの変更時にこの正本を参照する。
倍率は元のQに対する値であり、省略した設定は保存済みの設計パラメータを引き継ぐ。

`cube.analysis.bottom000.mounting-2x2@1`は、取付と制御器の4組の比較、およびその後の参照設計固有の制御器試験を記録する。
`cube.analysis.bottom000.current-controller@1`は、下側取付で保持したMASS制御器を記録し、公開済みの開発条件12件すべてに合格した。
スコアは0.988586で、以前の上側取付のMASS結果0.991612を下回る。
作り直した2種類のLQRは、下側取付で9/12件と8/12件に合格した。
重心が下がっても制御性能が改善するとは限らない。

6秒の数値試験は、8頂点の実機ミッション、草案の30秒保持、物理忠実度を検証しない。
新しい条件での確認は別に扱う。準備段階の版は不変の履歴として保持し、現在の表示用構成では後の版を選ぶ。

## 検証基盤

Qwen/vLLMはGPU 0〜5を各2 GPUの3レプリカとして使う。MJXはGPU 6〜7、ネイティブMuJoCoはCPUを使う。
デプロイ確認やネイティブMuJoCo–MJX整合は基盤の証拠であり、物理的な妥当性を示さない。
